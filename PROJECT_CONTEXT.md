## 5. Color system (THE most important part — read carefully)

### Living accent hue
- `--accent-hue` is a **registered `@property`** (`syntax: "<number>"`) so it
  can be animated/tweened in keyframes. Plain CSS vars can't tween.
- `:root` animates `--accent-hue` via `@keyframes accentDrift` (light) and
  `[data-theme="dark"]` via `accentDriftDark`. This makes the whole accent
  family slowly "breathe" / drift in hue over ~48–60s.
- `--accent = hsl(var(--accent-hue) var(--accent-sat) var(--accent-light))`.

### Light mode (default)
Soft blush/rose palette. `--bg #FBF1F0`, `--ink #2A1E22` (plum-black),
accent base hue **338** (vivid pink/magenta). Drifts hue 330–356.

### Dark mode (`[data-theme="dark"]`)
Gothic near-black + oxblood crimson. `--bg #0D0A0B`, `--ink #ECE4E2` (bone),
accent base hue **0** (crimson), drifts 350–12.

### CRITICAL BUG CLASS — negative hues
`hsl()` with a **negative hue** breaks in some engines → the color fails to
parse → gradient-clipped text (`color: transparent`) becomes INVISIBLE. This
already caused the "Contact" header to disappear once.
**RULE: never let a hue `calc()` go negative.** Always step FORWARD around
the wheel (add, don't subtract). Hue wraps mod 360, so e.g. `-28` must be
written as `+332`, `-56`→`+304`, `-84`→`+276`, `-112`→`+248`, `-110`→`+250`.

### The continuous hue ramp (sections + nav + want it fluent)
The owner wants colors to flow smoothly down the page like one long gradient,
each section's color close to its neighbor. Implemented via a per-section
`--sec-hue` stepping forward from the base:
- Section 1: `--accent-hue` (pink/magenta)
- Section 2: `+332`
- Section 3: `+304`
- Section 4: `+276`
- Section 5: `+248` (blue-violet end)
`.section { --sec-accent: hsl(var(--sec-hue) 70% 60%); }`

Each section's **number (`.section-no`), header gradient
(`.section-title.gradient-text`), and (for Toolkit) the column labels
(`.toolkit-label`) all use `--sec-accent`**, so a header and the number next
to it and its sub-labels always match.

**Sections have NO borders or boxes.** We tried wrapping each `.section` in
a thin rounded box but it read as a generic AI layout reflex AND the
sacred-geometry background lines clashed with the card borders. Sections are
now separated purely by generous whitespace (`padding-block`) and their
numbered headers (01, 02, ...). Don't re-add section outlines/boxes.

The **top-bar nav links** (`.nav a:nth-child(n)`) use the SAME forward ramp
via `--link-accent`, so the nav flows through the identical color journey
left-to-right. With the three-link nav (Home / About / Portfolio) the first
link uses the base hue, the second `+332`, the third `+304`. The
`+276`/`+248` nth-child rules are now harmless leftovers (no 4th/5th link).
The current page's link (`[aria-current="page"]`) keeps its underline drawn
and is brightened to read as selected.

### Gradient text
- Reusable class `.gradient-text` = ink → accent two-tone, `background-clip:
  text`, `color: transparent`, with `padding-top: 0.08em` to stop serif
  ascenders (top of "T") being clipped. Applied to: the brand (top bar),
  the eyebrow (major), and all 5 section titles.
- Variables `--grad-a` (= ink) and `--grad-b` (= a BRIGHT theme-tuned accent)
  drive it. In dark mode `--grad-b = hsl(344 62% 56%)` (bright crimson-rose)
  because the raw `--accent` is too dark to read on black.
- "Avar" (`.hero-title .italic`) uses a static ink→accent gradient at
  `background-size: 100%` (NOT oversized — an oversized sliding gradient
  parks on the pale end and looks flat/invisible; this was a repeated bug).
- Section titles use a **static, gentler** variant (no animation) so big
  display type doesn't look cheap.
- **Page titles** ("Who I am" on About, "Selected work" on Portfolio) carry
  `.page-title.gradient-text`: the same static ink→accent wash as section
  titles, anchored at the START of the palette ramp (`--grad-b` = live
  accent). So they match the palette and its order.
- **Project titles** (`.project-title`) use the SAME restrained ink→accent
  wash as the headers (`--grad-a` → `--proj-accent`), NOT a two-color sweep
  (that read as too "gradienty"). The only per-title variation is
  `--proj-hue`, stepped forward from `--accent-hue` per card (card 1 `+0`,
  2 `+30`, 3 `+60`, 4 `+90`), so the titles still read as an ordered
  progression down the list while each looks like a tasteful header-style
  tint. All forward offsets → no negative hue. Static (no drift); restored
  to a solid color under reduced-motion alongside `.gradient-text`.

### Lesson learned about gradients (owner feedback history)
- Too subtle / desaturated-into-ink = "can't see a gradient" → use the FULL
  accent at one end with real contrast.
- Too strong / multi-color = "looks like a first-timer with Photoshop" →
  keep it a single clean two-tone, not a rainbow.
- The current balance is approved. Don't swing to either extreme.

## 6. The animated mandala background

Fixed full-viewport layer behind everything: `.bg-field` (position: fixed,
z-index -1) containing `.mandala` (the primary 4 rings + glyph ring) and
`.bg-accent` (abstract second mandala), plus a `::after` gradient wash.

- **Primary mandala = 5 stacked `.ring` layers**, each a separate SVG on the
  same 1600×1600 canvas/center so they align into one mandala but rotate at
  DIFFERENT speeds (`spin` keyframe, durations 55s/95s/120s(glyphs)/150s/230s)
  → differential rotation (inner fast, outer slow). Order in HTML:
  ring-1, ring-2, ring-glyphs, ring-3, ring-4.
- Each ring also has an **opacity "pulse"** on its own non-harmonic duration
  + offset delay → irregular transparency "waves." Glyph ring uses the
  fainter `pulseGlyphs`. Outer rings are more transparent (baseline steps
  down). `.mandala` has overall `opacity: 0.62`.
- **Color**: SVGs are drawn in warm terracotta/charcoal. A per-theme `filter`
  retints them: light = `sepia/saturate/hue-rotate(300deg)` toward pink;
  dark = `invert(1) + sepia/hue-rotate`. The `hue-rotate` is ANIMATED
  (`mandalaHueLight` 54s / `mandalaHueDark` 64s) so the mandala's colors
  slowly cycle through the wheel.
- `.bg-accent` runs TWO animations (rotation `bgDriftReverse` + hue cycle),
  combined in the themed selector so neither overrides the other.
- The glyph ring (`mandala-glyphs.svg`) is a ring of decorative CJK/kanji
  characters like a magic "spell circle." Purely ornamental. Renders using
  the OS's CJK fonts (SVG-as-background can't load webfonts; Windows has them).

If you regenerate mandala SVGs: write a Python script (they use `math` for
radial placement), run it with `python <script>.py` from the project root,
validate with `[xml](Get-Content assets/x.svg -Raw)`, then DELETE the script.

## 7. Theme toggle (light/dark)

- Compact single-icon button in the header (`#theme-toggle`, 34px,
  `role="switch"`). Shows ONLY the sun in light mode and ONLY the moon in
  dark mode (the two icons are stacked via `grid-area: 1/1` on
  `.theme-toggle-track` and crossfaded). Deliberately small/quiet to match
  the social icons — it was previously a big bright sliding pill that stole
  focus; don't scale it back up.
- Inline script in `<head>` sets `data-theme` on `<html>` BEFORE first paint
  (reads localStorage `theme`, else OS `prefers-color-scheme`) to avoid a
  flash. Don't remove this.
- `js/main.js` wires the click: toggles `data-theme`, saves to localStorage,
  syncs `aria-checked`. During a toggle it adds a `.theme-transition` class
  to `<html>` for ~650ms which enables a one-shot color crossfade on all
  elements (`.theme-transition *` with `!important`), then removes it so
  normal hover transitions stay crisp.
- `js/main.js` also live-follows OS theme changes IF the user hasn't chosen
  (feature-detects `addEventListener`/legacy `addListener`).

## 8. Other JS behavior (js/main.js)

- Auto-tags `.section-head` with `.reveal`.
- **Copy email**: the envelope icon in the header IS the copy button
  (`.copy-email`, a `<button>`, NOT a mailto: link — there is no separate
  copy icon; one envelope that copies on click, with `title`/`aria-label`
  "Copy email address" so it's clear what it does). Clicking copies
  `data-email` via `navigator.clipboard.writeText`, with a hidden-textarea
  + `execCommand` FALLBACK for non-secure contexts (`file://` / non-HTTPS).
  On success it briefly adds `.copied` (a quiet lift to `--ink`, not a
  bright accent) and shows the `#copy-toast` for ~1.1s. The toast
  (`.copy-toast`, `role="status"`) is a deliberately NEUTRAL little label
  (faint `--bg-alt` fill, `--line` border, `--ink-soft` text — NOT the
  accent; the accent version read as too neon) anchored under
  `.header-left`, fade-only, with a reduced-motion fallback. One per page.
- Scroll reveal via IntersectionObserver (`.reveal`, `.reveal-left/right/
  scale`) → adds `.is-visible`. Staggered.
- **Floating bubbles**: injects a `.project-bubbles` layer with 7 `.bubble`
  spans into each `.project` card. On `mouseenter` it RESTARTS each bubble's
  animation from 0% (clears `animation`, forces reflow, re-applies) and adds
  `.is-hovering`; on `mouseleave` clears animation so bubbles reset to
  invisible. This fresh-restart is required so bubbles always rise from the
  bottom + fade in rather than appearing mid-float. Bubbles only exist /
  animate when NOT `prefers-reduced-motion`.
- Smooth in-page scroll for `a[href^="#"]` with focus handoff; the temporary
  `tabindex="-1"` is removed on blur (don't let it linger).

## 10. Accessibility / correctness invariants

- EVERYTHING animated must be disabled/neutralized under
  `@media (prefers-reduced-motion: reduce)`. There are several such blocks
  (hero intro, gradient drift, mandala rotation+hue, bubbles, reveals,
  section-title/name gradient fallback to solid color). When you add any new
  animation or gradient-clipped text, ADD a reduced-motion fallback,
  especially restoring a solid visible `color` for any `color: transparent`
  gradient text (else it's invisible with motion off).
- Keep high contrast (owner asked for it).
- Semantic HTML, skip link, aria labels — preserve them.
